Comparisons, Differences, and When to Use

17 comparisons

ALB vs NLB

Application Load Balancer works at layer 7 for HTTP, HTTPS, and gRPC. Network Load Balancer works at layer 4 for TCP, UDP, and TLS.

Use ALB for web apps, host/path/header routing, AWS WAF, redirects, authentication, and Lambda or container targets. Use NLB for static IPs, extreme performance, ultra-low latency, and non-HTTP traffic.

ALB vs Classic Load Balancer

Classic Load Balancer is legacy. ALB is the normal modern answer for HTTP and HTTPS applications.

Use ALB when the stem mentions modern web architecture, microservices, containers, multiple target groups, host-based routing, or path-based routing.

NLB vs Gateway Load Balancer

NLB forwards layer 4 application traffic to targets. Gateway Load Balancer inserts and scales third-party virtual network appliances.

Use NLB for high-performance TCP/UDP/TLS services. Use GWLB when traffic must transparently pass through firewalls, inspection appliances, IDS/IPS, or other network appliances.

Target group draining

Deregistration delay lets in-flight requests finish before an ALB or NLB stops sending traffic to a target.

Use it when reports, uploads, or long requests may fail during Auto Scaling scale-in. Sticky sessions keep a user on one target, but they do not protect requests during termination.

EC2 vs Lambda vs Fargate

EC2 gives OS, network, storage, and instance-level control. Lambda runs event-driven code without servers. Fargate runs containers without managing EC2 hosts.

Use EC2 for custom OS access, long-running services, special agents, or fixed server needs. Use Lambda for short event tasks. Use Fargate for containers with low operations.

EC2 pricing choices

On-Demand is flexible, Reserved Instances and Savings Plans reduce steady-state cost, Spot is cheapest for interruptible work, and Capacity Reservations guarantee capacity.

Use Spot for fault-tolerant batch. Use Reserved Instances or Savings Plans for predictable baseline usage. Use On-Demand for uncertain short-term workloads.

EC2 storage choices

EBS is persistent block storage in one Availability Zone. Instance store is temporary local block storage. EFS is shared Linux file storage across instances.

Use EBS for persistent attached volumes, instance store for high-speed temporary scratch data, and EFS when multiple EC2 instances need the same file system.

EC2 placement and networking

EC2 instances run in subnets inside a VPC and are protected by security groups. Placement affects latency, availability, and data-transfer cost.

Use multiple AZs for availability, same AZ for lowest EC2-to-EC2 transfer cost and low latency, and placement groups for tightly coupled high-performance workloads.

EC2 Auto Scaling vs manual capacity

EC2 Auto Scaling adjusts instance count, replaces unhealthy instances, and can rebalance across Availability Zones.

Use target tracking for demand-based scaling, scheduled scaling for predictable time windows, lifecycle hooks for cleanup before termination, and ELB health checks for self-healing fleets.

RDS vs DynamoDB

RDS is relational and supports SQL, joins, constraints, and familiar engines. DynamoDB is serverless NoSQL for key-value and document access patterns.

Use RDS for relational OLTP workloads. Use DynamoDB for high-scale predictable key access, single-digit millisecond latency, and serverless operational model.

Aurora vs RDS standard engines

RDS manages engines such as MySQL, PostgreSQL, MariaDB, Oracle, and SQL Server. Aurora is AWS-built MySQL/PostgreSQL-compatible relational database with distributed storage.

Use Aurora when the question needs higher performance, fast replicas, storage auto growth, Aurora Serverless, or Aurora Global Database. Use standard RDS when engine compatibility or licensing drives the answer.

Read replica vs Multi-AZ

Read replicas scale read traffic and can support reporting or read-heavy workloads. Multi-AZ provides standby failover for high availability.

Use read replicas when the stem says read scaling or offload reads. Use Multi-AZ when the stem says automatic failover, high availability, or standby database.

DynamoDB DAX vs ElastiCache

DAX is a managed in-memory cache built specifically for DynamoDB. ElastiCache is a general cache service using Redis or Memcached.

Use DAX when DynamoDB needs microsecond read latency. Use ElastiCache for session storage, caching relational query results, leaderboards, counters, or general application cache patterns.

Backup and restore vs pilot light

Backup and restore keeps backups only and rebuilds after a disaster. Pilot light keeps critical core infrastructure prepared, with most compute stopped until failover.

Use backup and restore for lowest cost and longest RTO. Use pilot light when you need faster recovery than backup and restore while keeping steady-state DR cost low.

Pilot light vs warm standby

Pilot light usually has stopped or minimal resources. Warm standby runs a scaled-down version of the full environment.

Use pilot light for lower cost and recovery in tens of minutes. Use warm standby when the stem needs a short RTO, minimal running capacity, and scale-up within minutes.

Warm standby vs active-active

Warm standby serves little or no production traffic until failover. Active-active serves production traffic from multiple sites at the same time.

Use warm standby when cost must be minimized but RTO is still short. Use active-active when the business requires the fastest recovery, global availability, or continuous multi-Region service and can accept higher cost.

DR answer strategy

Rank DR choices by cost and recovery speed: backup and restore, pilot light, warm standby, active-active.

Exam cue: RTO/RPO choose the strategy. Low cost points left; very low RTO/RPO points right. Database DR may require read replicas, Aurora Global Database, snapshots, backups, or cross-Region replication.

Design Secure Architectures

Make every layer secure: identity, network, application, data, keys, and audit evidence. Treat security as a constant design requirement, not only as a separate security topic.

What it means for the exam

  • Secure access. Pick IAM roles, federation, MFA, least privilege, and account guardrails instead of permanent credentials.
  • Secure workloads. Put compute in private subnets, expose only approved entry points, and filter traffic with security groups, NACLs, WAF, and endpoints.
  • Secure data. Encrypt at rest with KMS, encrypt in transit with TLS certificates, classify sensitive data, and define retention, backup, and replication policies.

Skills to master

Treat security as a design constraint everywhere

Evaluate secure choices at every stage, level, and tier of the architecture, including access, workloads, applications, data, and operations.

Apply security best practices to IAM and root users

Use MFA, complex passwords, protect the root user, avoid root access keys and long-term credentials, and apply least privilege to reduce blast radius.

Understand AWS accounts and the root user

AWS accounts start with one root user that has full permissions that cannot be reduced. Protect it with MFA and a complex password, avoid daily use, avoid root access keys, and create limited identities for normal administration.

Know that IAM is global

IAM is a global service. Its identities, credentials, and policies apply across Regions, so secure access decisions are account-wide.

Secure public, private, hybrid, and multi-cloud access

Design access differently for internet-facing, private VPC, on-premises, and third-party cloud environments while keeping least privilege and traceability.

Design IAM authorization models

Choose users, groups, roles, and policies that fit the access pattern.

Design multi-account security

Understand IAM policy evaluation

Multiple policies can apply to one identity. Explicit deny wins, permissions must be allowed, and SCPs set maximum permissions without granting access.

Use resource policies correctly

Domain 1 review

Secure Architectures Checklist

16 review points

Least privilege in a multi-account environment

Know

Use Organizations, Control Tower, IAM roles, permission sets, and SCPs. SCPs limit maximum permissions; they do not grant access.

IAM user vs IAM role

Know

Use users for long-term named identities when required. Prefer roles for AWS services, cross-account access, federation, and temporary credentials through STS.

Policy types to compare

Know

Identity policies define what a user, group, or role can do. Resource policies define who can access a resource. Permission policies attach to roles. SCPs set account or OU guardrails.

Overlapping allow and deny rules

Exam cue

Explicit deny wins. Otherwise access needs an allow, and guardrails such as SCPs or permission boundaries can still cap the final permission.

Federation into AWS

Know

Use IAM Identity Center, IAM roles, STS, Amazon Cognito, or directory integration so users sign in with existing identities instead of long-term IAM credentials.

Default VPC vs custom VPC

Know

A VPC is regional and belongs to one AWS account. Default VPCs are ready to launch into; custom VPCs give deliberate control over CIDR, subnets, routes, and security boundaries.

Subnet resiliency and segmentation

Know

Subnets are Availability Zone scoped. Use public subnets for approved internet entry points and private subnets for application or data tiers.

Secure VPC traffic controls

Know

Combine route tables, security groups, NACLs, NAT gateways, VPC endpoints, and gateways. Security groups are stateful allow rules; NACLs are stateless allow and deny rules.

Private access to AWS services and applications

Exam cue

Use gateway endpoints for S3 and DynamoDB. Use interface endpoints and PrivateLink for private service access without internet gateway, NAT gateway, or VPC peering.

Hybrid and external connectivity

Know

Use Site-to-Site VPN for encrypted connectivity over the internet, Client VPN for user access, Direct Connect for dedicated private connectivity, and Transit Gateway for hub routing.

Threat and application protection services

Know

Use Shield for DDoS protection, WAF for layer 7 web rules such as SQL injection controls, GuardDuty for threat detection, and Macie for sensitive data discovery in S3.

Secrets Manager vs Parameter Store

Exam cue

Choose Secrets Manager when secrets need managed rotation. Parameter Store is useful for configuration values and basic secure parameters.

KMS vs CloudHSM

Exam cue

Use KMS for managed key service integration with AWS services. Use CloudHSM when strict compliance requires dedicated customer-managed hardware security modules.

S3 encryption choices

Know

Client-side encryption happens before upload. Server-side encryption options include S3-managed keys, KMS keys, or customer-provided keys.

Compliance and evidence

Know

Use AWS Artifact for AWS compliance reports and agreements. Use CloudTrail, CloudWatch, VPC Flow Logs, Config, and Security Hub for evidence, monitoring, and visibility.

Data protection and disaster recovery

Know

Use AWS Backup for centralized backup, EBS snapshots, RDS/Aurora snapshots, DynamoDB point-in-time recovery, EFS backup, FSx backup, and S3 Cross-Region Replication when objects need continuous asynchronous copy.

DynamoDB, S3, Lambda, and IAM

20 exam cues

DynamoDB overview

DynamoDB is a fully managed, serverless NoSQL database for key-value and document data models.

Exam cue: choose DynamoDB for internet-scale applications that need single-digit millisecond performance at any scale.

DynamoDB performance at scale

DynamoDB supports horizontal scaling, flexible schema, tables of almost any size, and high request volume without server management.

Exam cue: flexible key-value/document workload with massive scale usually points to DynamoDB.

DynamoDB global tables

Global tables provide automatic multi-Region replication for fast local access and multi-active designs.

Exam cue: active-active, local reads/writes in multiple Regions, or global replication means DynamoDB global tables.

DynamoDB Accelerator

DAX is an in-memory cache for DynamoDB that can reduce read latency from milliseconds to microseconds.

Exam cue: choose DAX when the stem asks for microsecond read latency from DynamoDB.

DynamoDB Streams

DynamoDB Streams capture a time-ordered sequence of item-level changes for up to 24 hours and can trigger Lambda workflows.

Exam cue: react to table changes with DynamoDB Streams plus Lambda.

DynamoDB capacity modes

Provisioned capacity lets you set read/write capacity and can use auto scaling. On-demand mode instantly adapts to unpredictable traffic and charges for what you consume.

Exam cue: predictable traffic often fits provisioned capacity; unpredictable traffic often fits on-demand.

DynamoDB enterprise features

DynamoDB supports point-in-time recovery, ACID transactions, encryption at rest with KMS, and on-demand backup and restore.

Exam cue: PITR protects against accidental writes/deletes; transactions mean ACID support inside DynamoDB.

S3 object model

S3 stores objects in buckets. An object has a unique key, data, metadata, and name-value pairs.

Exam cue: S3 is object storage, not block storage and not a native file system.

S3 durability and availability

S3 automatically stores copies of objects across multiple Availability Zones and is designed for eleven 9s of durability.

Exam cue: S3 fits backup, restore, archive, static assets, data lakes, IoT, and big data analytics.

S3 security and compliance

S3 includes encryption, access management, S3 Block Public Access, auditing, and compliance support.

Exam cue: use S3 Block Public Access to prevent public bucket or object exposure.

S3 access management

S3 resources are private by default. Access can be granted through resource-based policies, user policies, ACLs, and pre-signed URLs.

Exam cue: AWS evaluates all applicable access policies before allowing or denying a request.

S3 resource-based policies

Bucket policies and access point policies use JSON and include a Principal because the policy is attached to the S3 resource.

Exam cue: resource policy controls who can access the bucket and what S3 operations are allowed.

S3 user policies

IAM user, group, or role policies grant an identity permission to call S3 actions on specific bucket or object ARNs.

Exam cue: identity policy does not need a Principal because the principal is the IAM identity.

Lambda overview

Lambda is serverless compute. You provide code, and AWS manages the underlying compute resources, availability, scaling, and runtime execution.

Exam cue: choose Lambda for event-driven code without managing servers.

How Lambda works

Upload code, configure triggers from AWS services, HTTP endpoints, in-app activity, or schedules, and Lambda runs only when invoked.

Exam cue: pay for requests and duration, not idle time.

Lambda trigger examples

Lambda can be triggered by S3 object changes, SNS messages, API Gateway requests, DynamoDB record changes, SQS queues, and EventBridge schedules.

Exam cue: match the event source to the trigger named in the stem.

Lambda benefits

Lambda has no servers to manage, continuous scaling, high availability, and subsecond metering.

Exam cue: when code is not running, compute cost is zero.

IAM overview

IAM manages authentication and authorization for AWS resources with users, groups, roles, policies, and temporary security credentials.

Exam cue: IAM has no additional charge and is a global service.

IAM access controls

IAM policies can allow or deny access. Groups let users inherit permissions, roles delegate access, and temporary credentials avoid long-term keys.

Exam cue: explicit deny overrides allow; use roles instead of hardcoded credentials.

IAM use cases

Use IAM for fine-grained access, conditions such as time, IP, SSL, and MFA, access analysis, MFA for privileged users, and federation with corporate directories through SAML.

Exam cue: least privilege plus MFA plus federation are common secure-access answers.

Amazon RDS and DynamoDB Checklist

18 review points

Amazon RDS purpose

Amazon RDS is a managed relational database service. AWS handles common administration tasks such as provisioning, patching, backups, monitoring, and failover options.

Exam cue: choose RDS when the workload needs a relational engine, SQL, joins, transactions, or existing relational application compatibility.

RDS supported engines

RDS supports familiar engines including Amazon Aurora, PostgreSQL, MySQL, MariaDB, Oracle Database, and SQL Server.

Exam cue: engine choice matters for licensing, feature support, migration path, performance, and cost.

RDS administration benefit

RDS can be created and managed from the console, CLI, SDK, or APIs, reducing manual server and database software administration.

Exam cue: if the stem says easy to administer or less operational overhead for a relational database, RDS is a likely answer.

RDS scaling

RDS can scale compute, memory, and storage. Read replicas offload read traffic, while storage autoscaling can help when allocated storage grows.

Exam cue: read replicas scale reads; larger instances scale vertically; Multi-AZ is for availability, not read scaling from the standby.

RDS Multi-AZ

Multi-AZ deployments synchronously replicate data to a standby in another Availability Zone and support automatic failover.

Exam cue: choose Multi-AZ for high availability and durability within a Region.

RDS backups and snapshots

RDS supports automated backups, manual snapshots, point-in-time recovery, and backup retention policies.

Exam cue: set backup frequency and retention to meet RPO while avoiding unnecessary snapshot storage cost.

RDS automatic recovery

RDS improves reliability with managed infrastructure, monitoring, backups, and automatic host replacement for failed underlying hosts.

Exam cue: managed availability features reduce the operational work of running critical production databases.

RDS security

Place RDS in private subnets, control network access with security groups, and use encryption at rest and in transit where required.

Exam cue: database instances should usually be isolated from direct public access.

RDS migration

Use AWS Database Migration Service to migrate or replicate existing databases into AWS with minimal downtime patterns.

Exam cue: DMS moves database data; SCT helps convert schemas when the source and target engines differ.

RDS storage options

RDS uses SSD-backed storage options such as General Purpose SSD and Provisioned IOPS SSD depending on workload performance needs.

Exam cue: choose Provisioned IOPS when the relational workload needs consistent high I/O performance.

DynamoDB purpose

DynamoDB is a fully managed serverless NoSQL database for key-value and document data models.

Exam cue: choose DynamoDB for high-scale, low-latency access with known key-based access patterns.

DynamoDB scale

DynamoDB horizontally scales tables of almost any size and is designed for single-digit millisecond performance.

Exam cue: internet-scale key-value workloads often point to DynamoDB rather than a relational database.

DynamoDB capacity modes

Use provisioned capacity for predictable traffic and on-demand capacity for unknown, spiky, or less predictable access patterns.

Exam cue: on-demand mode ramps capacity automatically; provisioned mode can use auto scaling for cost control.

DynamoDB Global Tables

Global tables provide automatic multi-Region replication for multi-active applications that need fast local reads and writes.

Exam cue: multi-Region, active-active, local access to the same NoSQL table means Global Tables.

DynamoDB Accelerator

DAX is a managed in-memory cache for DynamoDB that can reduce read latency from milliseconds to microseconds.

Exam cue: choose DAX when DynamoDB read latency must be extremely low and the workload is read-heavy.

DynamoDB Streams

DynamoDB Streams capture time-ordered item-level changes for up to 24 hours and can trigger Lambda workflows.

Exam cue: item changes that trigger processing, workflow, or notification usually point to Streams plus Lambda.

DynamoDB recovery and compliance

DynamoDB supports point-in-time recovery, on-demand backup and restore, ACID transactions, and encryption at rest with AWS KMS.

Exam cue: choose PITR when the need is recovery from accidental writes or deletes.

RDS vs DynamoDB

Use RDS for relational structure and SQL requirements. Use DynamoDB for serverless key-value or document access at very high scale.

Exam cue: joins and complex SQL point to RDS; simple predictable key access at massive scale points to DynamoDB.

Architecture Exam Flashcards

13 cards

Which load balancer is at Layer 7 of the OSI model?

The Application Load Balancer.

Exam cue: ALB is for HTTP, HTTPS, gRPC, host/path routing, and modern web applications.

Which load balancer handles millions of requests per second?

The Network Load Balancer.

Exam cue: NLB is Layer 4 and fits ultra-low-latency TCP, UDP, and TLS workloads.

CloudFront vs Global Accelerator

CloudFront caches static and dynamic content at edge locations. Global Accelerator improves network routing to regional endpoints by using the AWS global network and static anycast IPs.

Exam cue: cache content with CloudFront; accelerate non-cacheable TCP/UDP or regional application access with Global Accelerator.

What are the two S3 replication types?

Cross-Region Replication and Same-Region Replication.

Network Load Balancer

NLB operates at layer 4 for TCP, UDP, and TLS. It is designed for extreme performance, very low latency, and millions of requests per second.

Exam cue: choose NLB when the question mentions static IP, one Elastic IP per subnet, or high-performance TCP traffic.

Gateway Load Balancer

GWLB helps deploy and scale third-party virtual networking appliances such as firewalls, inspection tools, and security appliances.

Exam cue: choose GWLB when traffic must transparently pass through appliances.

Classic Load Balancer

ELB security controls

Exam cue: security groups protect instance/network interfaces; NACLs protect subnet boundaries.

Exam cue: sticky sessions keep the same client on the same target but can cause uneven utilization.

ELB monitoring and logging

Exam cue: metrics are for performance and alarms; CloudTrail is for who did what.

Exam cue: it helps balance predictable performance, lowest cost, and capacity across services.

EC2 Auto Scaling self-healing

Auto Scaling policies

Exam cue: scale out for demand increases and scale in when capacity is no longer needed.

Loosely coupled architecture

Exam cue: loosely coupled systems scale and fail independently.

Exam cue: stateless web tiers are easier to scale horizontally behind a load balancer.

Amazon EC2 Overview - Storage and Networking

EC2 instances run in a VPC, use security groups for traffic control, and connect to different storage types depending on durability and sharing needs.

EC2 Storage Choices

Match storage to persistence, sharing, and performance requirements.

  • EBS: persistent block storage for one EC2 instance in one AZ.
  • Instance store: temporary block storage physically attached to the host.
  • EFS: shared elastic file storage for Linux workloads across AZs.
  • S3: object storage for backups, snapshots, AMIs, and durable data.

EC2 Networking Basics

EC2 instances launch into subnets inside a VPC and inherit network behavior from subnet routes and security controls.

  • Default VPC lets you launch quickly with prebuilt subnets and internet settings.
  • Custom VPC gives control over CIDR ranges, subnets, routing, and isolation.
  • Security groups act as virtual firewalls for EC2 instances.
  • Use multiple AZs to improve application fault tolerance.

Resiliency and Storage Flashcards

9 cards

If you need synchronous data replication across Availability Zones for Amazon RDS, what is the best solution?

Answer

Multi-AZ deployment. RDS synchronously replicates to a standby in another AZ for high availability and failover.

If you need asynchronous data replication to another Amazon RDS instance in another AWS Region, what is the best solution?

Answer

Add a read replica. Cross-Region read replicas use asynchronous replication and can support DR or read scaling.

You need an RDS disaster recovery plan with RTO of 60 seconds and RPO of 1 second. What database is best?

Answer

Amazon Aurora Global Database. It spans multiple Regions with storage-based replication and very low RPO/RTO targets.

What is high availability?

Answer

Designing systems to stay up and provide service as often as possible, usually by using redundancy and automatic failover.

What is fault tolerance?

Answer

The ability of a system to keep operating when one or more components fail.

What is disaster recovery?

Answer

Planning how to restore systems after a larger failure. The exam usually gives RTO and RPO to choose the right DR strategy.

Which AWS service can create DNS failover for a static website hosted on Amazon S3?

Answer

Amazon Route 53 with a failover routing policy and health checks.

What Amazon S3 storage class would you choose to store cold data?

Answer

Amazon S3 Glacier. Use Glacier classes for archive and cold data where retrieval delay is acceptable.

What storage solution would you choose for a parallel file system for frequently accessed data?

Answer

Amazon FSx for Lustre. Use it for high-performance parallel file storage for HPC, analytics, and machine learning workloads.
